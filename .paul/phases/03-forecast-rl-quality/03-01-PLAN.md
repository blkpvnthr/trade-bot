<objective>
## Goal

Replace the intraday RL agent's per-step reward defect with a mathematically correct,
per-step-additive **Differential Downside Deviation Ratio (DDR / differential Sortino)**
reward (Moody & Saffell 2001), exposed behind an `RL_REWARD_MODE` selector that defaults to
the current behavior (zero blast radius), and prove the DDR math with data-free unit tests.

## Purpose

DISCOVERY established two defects in today's reward (`SharpeRewardCalculator`, a naive
60-step overlapping-window Sharpe used as the per-step signal):
1. It is non-additive / non-Markovian — the reward at step t is the full rolling-window Sharpe,
   so PPO is credited/blamed for 59 past actions it can no longer influence, corrupting the
   advantage estimates. DDR is the canonical per-step marginal fix.
2. Plain Sharpe penalizes upside variance, fighting this book's convex-upside thesis. DDR's
   downside-only denominator matches ROADMAP Phase-3 scope ("penalize drawdowns") and the
   composite optimization objective (Sortino/Calmar).

## Output

- `rl_agent_core.py` — `SharpeRewardCalculator` gains a `mode` param
  (`"sharpe_rolling"` default = today's behavior; `"ddr"` = new DDR). DDR maintains online
  first-moment + downside-second-moment estimates and returns the differential downside ratio.
- `rl_intraday_structure_trainer.py` — reads `RL_REWARD_MODE` (default `"sharpe_rolling"`)
  and passes it to the calculator; guards the `VecNormalize` reward clip against DDR's scale.
- `tests/test_ddr_reward.py` — data-free unit tests: DDR math properties, no-NaN, determinism,
  and backward-compat parity (default mode reproduces current outputs exactly).
</objective>

## AC-1: DDR reward is implemented and mathematically correct

```gherkin
Given SharpeRewardCalculator(mode="ddr") with decay eta and downside target 0
When update(R_t) is called per step over a return stream
Then it maintains online estimates A_t = A_{t-1} + eta*(R_t - A_{t-1}) and
     DD_t^2 = DD_{t-1}^2 + eta*(min(R_t,0)^2 - DD_{t-1}^2)
And returns the differential downside deviation ratio D_t per Moody & Saffell 2001:
     R_t > 0 : D_t = (R_t - 0.5*A_{t-1}) / DD_{t-1}
     R_t <= 0: D_t = (DD_{t-1}^2*(R_t - 0.5*A_{t-1}) - 0.5*A_{t-1}*R_t^2) / DD_{t-1}^3
And the first step (no history) falls back to raw R_t with no NaN/inf
And a loss injected into an otherwise-positive stream raises DD and lowers subsequent reward
     versus the all-positive stream (downside sensitivity)
```

    1. `__init__`: add `mode: str = "sharpe_rolling"`, `eta: float = 0.02`,
       `downside_target: float = 0.0`. Keep existing `window`, `risk_free`, `sharpe_weight`.
       Initialize DDR state: `self._A = 0.0`, `self._DD2 = 0.0`, `self._ddr_n = 0`.
    2. `reset()`: also zero `_A`, `_DD2`, `_ddr_n` (so per-episode DDR state clears — env calls reset()).
    3. `update(step_pnl, structure_bonus=0.0)`: branch on `self.mode`.
       - `"sharpe_rolling"`: EXACTLY the current code path, unchanged (backward-compat).
       - `"ddr"`: compute the Differential Downside Deviation Ratio (Moody & Saffell 2001):
           R = step_pnl
           if self._ddr_n == 0:            # warm-up, no prior moments
               self._A = R; self._DD2 = min(R, self.downside_target)**2; self._ddr_n = 1
               return float(R + structure_bonus)      # raw fallback, no NaN
           A_prev, DD2_prev = self._A, self._DD2
           dd_prev = sqrt(DD2_prev)
           if dd_prev < 1e-9:              # no downside history yet -> avoid /0
               D = R - 0.5*A_prev
           elif R > self.downside_target:
               D = (R - 0.5*A_prev) / dd_prev
           else:
               D = (DD2_prev*(R - 0.5*A_prev) - 0.5*A_prev*R*R) / (dd_prev**3)
           # advance online moments AFTER computing D (D uses t-1 moments)
           self._A   = A_prev  + self.eta*(R - A_prev)
           self._DD2 = DD2_prev + self.eta*(min(R, self.downside_target)**2 - DD2_prev)
           self._ddr_n += 1
           return float(D + structure_bonus)
    4. `current_sharpe` property: leave as-is (still valid for logging; DDR doesn't change it).
       If DDR mode and the rolling window is empty, it already returns 0.0 — fine.

    ## What to avoid (and why)

    - Do NOT flip the default mode — validation that DDR beats baseline is 03-03, not this plan.
    - Do NOT add scipy/pandas — use math.sqrt / plain floats (numpy already imported if needed).
