<objective>
## Goal

Make `rl_intraday_structure_trainer.py` consume the Alpaca-derived intraday bars and emit
its model + metrics at the canonical date-stamped `system-data/{DATE}/` paths every other
subsystem already reads, with a `[data-source] training_csv=alpaca_derived` provenance log —
then make the training-pipeline smoke test prove it (10/10) and actually fail-exit on regressions.

## Purpose

Phase 2's goal is "training datasets use the same Alpaca feed config as live execution" and
"rl_intraday_structure_trainer.py data provenance validated." Today the trainer writes
`models/rl_intraday/final_model.zip` + `metrics/rl_intraday_metrics.json`, but
`trade.py.validate_rl_intraday_structure_model()` (and 4 other consumers) look for
`system-data/{DATE}/{DATE}_rl_intraday_structure_model.zip` + `{DATE}_rl_intraday_training_metrics.json`.
The freshly-trained model is therefore never found by validation — a real provenance break.
Aligning the producer to the consumers' convention closes the Phase 2 chain end-to-end.

## Output

- `rl_intraday_structure_trainer.py` — reads canonical Alpaca bars; writes canonical
  date-stamped model + metrics; logs the provenance line. Env overrides preserved.
- `scripts/smoke_test_training_pipeline.py` — exits non-zero on any failure; 10/10 pass.
- (Checkpoint) live training run confirms the canonical artifacts are produced and that
  `validate_rl_intraday_structure_model()` now resolves the model.
</objective>
